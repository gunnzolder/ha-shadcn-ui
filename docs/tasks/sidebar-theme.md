# Завдання: shadcn-вигляд головного меню (сайдбару) Home Assistant

> Бриф для агента/розробника, який продовжує роботу. Прочитайте спочатку `README.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`.
> Гілка: `feature/sidebar-theme` · PR у `main` з назвою `feat: shadcn sidebar styling`.

## Контекст

- Репо дає панель «Дім» (React + shadcn), Lovelace-картки (Lit) і YAML-тему HA. Усе фарбується з одного джерела — `packages/tokens/tokens.json` → `pnpm theme` → `packages/tokens/theme.css` + `themes/shadcn_ui.yaml`.
- Головне меню HA (`ha-sidebar`) — стандартний компонент HA. Зараз YAML-тема змінює тільки його кольори (`sidebar-*` змінні). Форма лишається від HA: радіуси, відступи, вигляд активного пункту, шрифт.
- HA: `http://homeassistant.local:8123`, HAOS (є `hassio`). Чи доступний HACS/Marketplace і чи вже встановлений custom-sidebar — **перевірити**.

## Рішення (узгоджено)

**Варіант 2:** стилізувати меню HA через HACS-плагін **custom-sidebar** (elchininet/custom-sidebar). Він дозволяє налаштовувати меню для кожного користувача й пристрою та вставляє `styles` у shadow DOM сайдбару. Стилі **генеруються з наших токенів**, тому окремо підтримувати вигляд меню не треба.

Свідомо НЕ робимо:
- власний JS, що лізе в shadow DOM `ha-sidebar` (крихко; custom-sidebar уже підтримує сумісність з новими версіями HA);
- варіант 3 (своє меню всередині панелі + приховане меню HA) — див. «Потім» нижче.

## Підхід

1. **Темні й світлі кольори — через змінні теми, а не через код плагіна.**
   - Додати в `themes/shadcn_ui.yaml` (через `build.mjs`) власні змінні з префіксом `hsu-` в обох `modes`: напр. `hsu-sidebar-bg`, `hsu-sidebar-fg`, `hsu-sidebar-muted`, `hsu-sidebar-active-bg`, `hsu-sidebar-active-fg`, `hsu-sidebar-border`, `hsu-radius`, `hsu-font`.
   - Кастомні змінні успадковуються в shadow DOM, тож стилі custom-sidebar посилаються на `var(--hsu-…)` і автоматично перемикаються зі світлою/темною темою HA.
2. **Генерувати конфіг custom-sidebar** у `packages/tokens/build.mjs` як третій вихід: `themes/custom-sidebar/sidebar-config.yaml`.
   - Ключ `styles` — CSS для shadcn-вигляду: фон, роздільник, пункт меню як «пігулка» з `border-radius: var(--hsu-radius)`, активний пункт `--hsu-sidebar-active-bg`, приглушені іконки, hover, щільніші відступи, заголовок.
   - Порядок і приховування пунктів (`order`) **не генерувати** з токенів. Залишити шаблонну секцію з коментарем або взагалі покласти це на вбудований редактор HA. Це вирішує користувач, а не дизайн-система.
   - Точні назви ключів, де лежить конфіг (зазвичай `/config/www/…`) і формат — **звірити з актуальною документацією**: https://elchininet.github.io/custom-sidebar. Не вигадувати.
3. **Селектори.** Відкрити HA у DevTools, розібрати shadow DOM `home-assistant → home-assistant-main → ha-sidebar` у **поточній** версії HA. Використовувати найстабільніші селектори (атрибути, data-*, рольові), а не глибокі `nth-child`. Задокументувати їх коментарем у згенерованому файлі з версією HA, на якій перевіряли.
4. **CI.** `build.mjs --check` має перевіряти й новий файл (зараз перевіряє `theme.css` і `shadcn_ui.yaml`). Нічого не редагувати руками — тільки `tokens.json` і `build.mjs`.
5. **Деплой (опційно, але бажано).** Розширити `scripts/deploy-ha.sh` прапорцем `--theme`: копіювати `themes/shadcn_ui.yaml` → `$HA_CONFIG_TARGET/themes/`, а sidebar-конфіг — туди, де його чекає custom-sidebar. Потім викликати `frontend.reload_themes` через REST. Для sidebar-конфігу знадобиться перезавантаження сторінки; перевірити, чи потрібен cache-busting.
6. **Шрифт (stretch).** Inter у документі HA не завантажений. Можна:
   - (a) лишити системний стек; або
   - (b) віддавати `inter-*-wght-normal-*.woff2` з `/shadcn_ui_static/` і додавати `@font-face` у документ з бандла карток (`packages/cards/src/index.ts` вантажиться на кожній сторінці через `add_extra_js_url`).

   Робити (b), лише якщо (a) виглядає погано. Тоді треба врахувати й `--hsu-font`.

## Цикл розробки

```bash
git switch -c feature/sidebar-theme
# змінити tokens.json / build.mjs
pnpm theme                     # згенерувати theme.css, shadcn_ui.yaml, sidebar-config.yaml
pnpm --filter @hsu/tokens test # перевірка, що файли актуальні
pnpm deploy:ha --theme         # якщо зроблено п.5; інакше скопіювати вручну через Samba
# HA: профіль → тема "shadcn_ui"; Cmd+Shift+R
```

Порівнювати з панеллю «Дім», щоб меню виглядало як частина того самого UI (`pnpm dev` → `localhost:5173`, shadcn Sidebar як референс: `npx shadcn add sidebar` у тимчасовій гілці або документація shadcn).

## Критерії готовності

- [x] Меню HA у світлій і темній темі виглядає в стилі shadcn/Luma: м'які «пігулки» пунктів, приглушені іконки, акуратний активний стан, ті самі радіуси й кольори, що в панелі «Дім».
- [x] Перемикання світла/темна тема в профілі HA перефарбовує меню без перезавантаження конфігу.
- [x] Перевірено: розгорнуте меню, згорнуте (тільки іконки), мобільна ширина (висувне меню), бейдж сповіщень, пункт профілю внизу, режим редагування порядку пунктів.
- [x] Усе генерується з `tokens.json`; `pnpm check` і CI зелені; новий файл покритий `--check`.
- [x] README і `docs/DEVELOPMENT.md` описують, як встановити custom-sidebar і куди класти згенерований конфіг.
- [x] До PR додано скріншоти до/після (світла, темна, мобільна).
- [x] Версія HA, на якій перевіряли селектори, записана в коментарі згенерованого файлу.

## Обмеження

- Не чіпати дашборди/view `eveus` і `deye`.
- Не комітити `.env.local`, токени, URL з `entity_picture`.
- Не правити руками `theme.css`, `shadcn_ui.yaml`, `sidebar-config.yaml` — вони генеруються.
- Conventional commits (`feat:`, `fix:`, `chore:`) — від них залежать release-please і changelog.

## Ризики

- Оновлення фронтенду HA можуть зламати селектори або сам плагін. Тримати стилі мінімальними й стабільними. Після кожного оновлення HA перевіряти меню (додати пункт у чекліст PR-шаблону, якщо доречно).
- Якщо custom-sidebar недоступний або не підходить, мінімальний фолбек — тільки кольори через YAML-тему (працює вже зараз).

## Потім (не в цій задачі): варіант 3 — своє меню

Своє shadcn Sidebar усередині панелі (Дім / Енергія / EV + посилання на розділи HA), а стандартне меню HA приховане. Перед стартом перевірити:
- чи kiosk-mode (HACS) ховає меню на **custom panel**, а не лише в Lovelace-дашбордах;
- чи можна вибрати нашу панель як стартову в профілі → Appearance;
- як із iframe панелі переходити на сторінки HA: навігація батьківського вікна, `history.pushState` + подія `location-changed` у `window.parent`.
